# ADR 001: Console 模块微服务化与事件驱动异步架构

## 状态 (Status)
已接受 (Accepted) - 2026-03-24

## 背景 (Context)
随着交易策略（如 V93）向“三支柱”（DataFeed, Executor, Strategy）转型，传统的中心化同步控制逻辑（Runner 主动调度）开始显露出局限性：
1. **耦合度高**：Runner 必须深入了解每个组件的内部方法。
2. **私有数据归属模糊**：仓位和资金数据在 DataFeed 和 Executor 之间摇摆。
3. **扩展性差**：增加新的监控或日志逻辑需要修改核心逻辑。

## 决策 (Decision)
我们将 `console` 模块重构为以 **ATSEngine (ATS 引擎)** 为核心的微服务架构：
1. **事件总线 (Event Bus)**：作为唯一的通信渠道。
2. **三权分立微服务化**：
   - `DataFeed`：感知服务。
   - `Strategy`：思考服务。
   - `Executor`：动作服务。
3. **宿主内建黑匣子 (Host-Builtin Logging)**：日志记录不再是可选 Skill，而是 ATSEngine 的核心宿主功能，自动捕获总线上所有原子事件。
4. **异步并发运行**：基于 `asyncio`。

## 影响 (Consequences)
### 正面影响
- **极度解耦**：组件间互不感知，只面向协议（Protocol）编程。
- **仓位数据化**：满足了“仓位也是一种输入数据”的设计直觉。
- **可观测性增强**：通过监听总线，可以无损地增加日志、分析及 UI 监控插件。
- **高性能**：异步非阻塞模型提升了系统的实时响应能力。

### 负面影响 (需注意)
- **调试复杂度**：事件驱动的流转比顺序调用更难通过单步调试跟踪。需依赖强大的日志系统（Black Box）。
- **初始化顺序**：需要确保总线和执行器在行情开始前就绪。
