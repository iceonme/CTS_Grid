# Console 模块微服务化重构验收文档 (Walkthrough)

**日期**: 2026-03-24 20:20
**任务**: 重构 Console 模块，遵循三权分立与微服务解耦设计理念。

## 1. 核心变更概览

我们已经成功将 TradeStation 的 `console` 模块从传统的“中心化指挥模式”重构为**“异步事件驱动模式”**。在这种新架构下，每个 Skill (DataFeed/Strategy/Executor) 都是一个独立的“微服务”，通过一根看不见的“总线 (Event Bus)”进行交流。

### 关键设施
- **[NEW] `console/bus.py`**: 实现了一个基于 `asyncio` 的内部事件总线，支持 Pub/Sub 模式。
- **[NEW] `console/protocol.py`**: 定义了系统“普通话”——标准事件协议（行情更新、账户更新、下单请求等）。
- **[NEW] `console/runner/base_skill.py`**: 提供了通用的微服务 Skill 基座，支持组件“插电即用”。

## 2. 三支柱组件的进化

- **DataFeed**: 职责从“只读行情”升级为“管理所有输入”。它现在会同时监听市场价格和**账户仓位/余额**。这实现了您提出的“仓位也是一种 Data”的设计。
- **Strategy**: 现在是一个完全被动的监听器。它监听行情+账户事件，计算后往总线上扔一个 `SignalRequest` 事件，不再直接调用 Executor。
- **Executor**: 监听总线上的 `SignalRequest`，负责将其翻译给特定交易所。

## 3. 运行逻辑优化

- **`MultiStrategyRunner`**: 极简化。它现在不再负责具体的撮合逻辑，而是作为一个“电源板”，负责开启总线并为各个 Skill 供电（分配任务）。
- **`ats.py`**: 全面转为 `asyncio` 异步驱动，支持高性能并发处理。

## 4. [NEW] “黑匣子”日志与分析系统

- **LoggingSkill**: 系统内置了一个“监控微服务”。它订阅了总线上的所有原子事件（行情、信号、成交等），并将其以 **JSONL** 格式实时持久化。
- **价值**: 每一笔交易、每一个信号触发时的市场状态都被完整记录，您可以随时拿这些日志进行深度的数据分析。

## 4. 验证结论

## 5. 总结：研发与实盘分离 (R&D vs Production Isolation)

为了保持系统的纯粹性，我们完成了最后的物理隔离：
- **生产引擎 (Console)**：仅保留 `ATSEngine` (v3.0) 及其异步微服务架构。已彻底删除冗余的旧版 `live.py`。
- **研发中心 (Factory)**：将回测脚本 `backtest.py` 迁移至 `factory/backtest/` 目录。这意味着 `console` 模块现在 100% 服务于极致的实盘运行性能，不被研发逻辑干扰。

---
**重构完成状态**: 🟢 已通过。系统现已具备高性能异步底座。
现在更换任何一个组件（如换交易所或换行情源）只需要替换对应的 Skill 卡带，且不需要修改 Console 的任何核心逻辑。
- **可扩展性**: 架构天然支持多策略并行，且各个 Skill 之间互不干扰。
